## Optional Hold & release (browser adaptation)

The host may select **Hold & release (episode-inspired)** instead of **Sealed bids** in an online lobby. Each human starts with 600 seconds for nineteen rounds. Hold during the countdown to enter privately. Release before five seconds to pass without spending time; at five seconds or more, the full held time is spent. The longer hold wins only if the highest tenth-second result is unique. An exact top tie awards no token. Final standings sort by tokens, then remaining time; exact ties share rank.

Countdown, review pause, timer estimation, cancellation on interrupted input, and automatic closure after a missed connection lease are browser rules. On an interrupted hold, the host charges the same time cost but excludes the hold from winning. A naturally exhausted bank can win. A disconnected seat stays in the roster and may resume, but its interrupted hold cannot be restarted. The host measures bids when messages arrive, so connection latency can affect close results. The host sees the game state; treat the host as trusted for fair play. No money, betting, or show prizes are implemented.

Other seats receive no updates for private holds, releases or connection-lease pulses. They see the shared round phase, winner/time (or top tied time), token counts and final ranks. The ordinary room roster can still show who is connected. The reducer and host tests exercise timing and redaction; the three-browser check uses local test transport, not production PeerJS.
